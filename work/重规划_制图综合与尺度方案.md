# 重规划：制图综合、完整房院与尺度设计

日期：2026-10-20。状态：工作方案，未处理实施数据、未新建模型。

**推荐路线：先完成陆巷代表样区的完整体素房院和可进入的观看尺度，再扩展为“全域总图＋同一设计世界中的连续片区”。** 全域总图说明东山半岛、太湖、三山岛、主山脊与聚落的关系；进入片区后，每一座入选屋舍都具备完整的建筑构件。制图综合决定选择哪些内容、如何组织空间，完整资产决定入选对象的制作精度，运行调度负责可见范围与提交成本。

参考作品约 1.28 × 1.28 km 的主世界说明一种画面密度与构图容量，不构成本项目的尺寸上限。东山源范围有十几公里尺度，设计范围由必保关系、完整房院的占地、街水空隙与目标镜头共同确定；全镇不预设压入固定 1.28 km。

## 1. 重做时采用的三套坐标

| 坐标层 | 内容与单位 | 负责解决的问题 | 保留记录 |
| --- | --- | --- | --- |
| 地理源坐标 G | WGS84 经纬度；计算用 EPSG:32651 米制东、北坐标。源高程单列基准与日期 | 对象在哪里、来源是什么、原始形状和关系如何 | 原始几何、source ID、时间、CRS、高程基准与质量 |
| 内容综合设计坐标 C | 人工设计的平面坐标与高度，使用“设计米”；保存 G→C 映射和对象设计参数 | 内容删选、聚落重组、空间压缩、必要移位、局部夸张与留白 | 设计几何、源对象集合、操作类型、约束对象、变形/移位与取舍理由 |
| 显示坐标 R | C 经局部原点平移、统一单位换算、渲染轴转换后进入引擎；建筑还有自己的局部构件坐标 | 数值稳定、分块、相机、FOV、屏幕像素与LOD | 块原点、单位换算、相机和视口、资产局部朝向与LOD身份 |

平面关系可写成 `C_xy = F(G_xy)`。`F` 可以是分片、连续、有约束的变形；它改变作品中的设计距离。显示层可写成 `R = s × axis(C − origin)`，其中 `s` 是统一单位换算。统一缩放后如果相机也按相同比例取景，房屋的屏幕尺寸并不会提高。

建筑应先将锚点、入口方向和所属街坊映射到 C，再在局部构件坐标中生成完整形体。空间压缩场作用于地理骨架与摆放关系；房屋的门、窗、墙厚、檐口和体素格不随压缩场任意拉扯。需要调整房宽或开间时，用构件参数重新生成。

源高程、设计高程和显示高程分别保存。约 30 m 的 DSM 提供宏观坡势，细分柱格提供方阶表达；插值与细分不增加实测地形信息。局部台基、岸阶、巷道坡面与山势强化进入设计层，并标明依据或推定。

## 2. 先把综合操作的职责写清楚

| 操作 | 本项目中的用法 | 验收重点 |
| --- | --- | --- |
| 选择 | 保留地方辨识、路径组织和聚落轮廓需要的房屋、院落、街巷、水口；删去同质重复对象 | 必保对象在场；古村、现代镇区、山村和茶果林的类型差异仍可读 |
| 聚合 | 将同一街坊内的来源对象组织为一个有身份的设计组团，决定代表房屋的数量、疏密和朝向 | 每个组团由若干完整房屋、院墙和空隙构成；一个大屋顶不能代替一片村落 |
| 简化 | 精简岸线细弯、重复附房、非关键支沟与装饰，保留主要轮廓和结构 | 关键水口、巷口、院落串联与地方形制保持清楚 |
| 移位 | 为街道、港道、院落或地标留出可读空间，在所属地块/同侧内调整锚点 | 不越过必保道路、水道或岸线；入口仍朝向对应通路 |
| 局部夸张 | 加宽窄巷、水口、檐口或院落间隙，增强必要山势与识别特征 | 对象层级与类型保持可信；加宽后重新解决相邻对象占用 |
| 空间压缩 | 压缩同质重复街段、低信息空地或过长连接距离，为完整对象分配设计空间 | 有明确控制区和过渡区；方向、邻接、沿岸次序、网络关系与岛陆分离成立 |

删选数量可以显著变化，入选屋舍的完整制作标准保持一致。最终对象数由设计空间的容纳能力与画面测试决定，不从“每组代表多少源栋数”倒推出同一尺寸屋顶。

## 3. 非均匀压缩的约束与实施顺序

### 3.1 先建立必须保留的关系图

把峰脊、湖岸转折、水口、码头、主街端点、桥头、聚落核心与可定位地标作为控制对象，分开记录四类关系：

1. **地形和水陆关系：**山脊—坡脚—村落—湖岸的层次，三山岛与半岛之间的水域间隔，主要岸线转折与入湖口。行政镇界负责范围筛选，不代替湖岸。
2. **邻接与顺序：**沿主街的节点先后、沿岸的村港次序、街坊左右侧、院门接巷、院落前后进和主要朝向。道路弯曲时按街路的左右侧和弧长顺序检查，不能用全局东西坐标代替。
3. **分交通方式的连通关系：**主步行路径、主要车行连接、港道至湖面的连通；桥梁上的道路跨水但不连接成水路。源数据中的立交相交点也不自动成为路口。
4. **空隙与层级：**院落留空、巷道净宽、码头水陆接口、重要地标周边留白，学校/古建/普通住宅的体量层级。

必保关系先过资料审查，未知关系列为待核，不能由程序补成确定事实。保留网络允许合并没有识别作用的二度节点；必保节点间的可达性、桥水关系和必要绕行关系须保留。

### 3.2 分区压缩，连续衔接

- **稳定核心：**已经设计好的完整院落、街口、水口、桥与地标组合。主要调整位置和整体朝向，保留内部构件尺度与关系。
- **可压缩区：**重复街段、同质房群和低信息连接空间。先选择较少的完整对象，再缩短节点间距离，给建筑占地和通路留出空间。
- **保护走廊：**必保道路、水道及岸线的设计占用带。宽度由目标屏幕尺度、通行表达和相邻对象共同决定，建筑不能侵占。
- **过渡区：**不同压缩强度的交界。地形、路网与岸线连续变形；不得出现接缝、路径突跳或突然变窄的水口。

可采用带控制点和控制线的连续变形网格实现 F。每个控制单元需要保持方向、不翻折；在非断裂区域维持局部一一映射。每轮变形后查多边形自交、岸线交叉、河口封闭、路水错位、对象碰撞和坡面异常。无法同时满足约束时，优先减少重复对象、放大设计区域或调整构图，再讨论更强压缩。

### 3.3 严格控制道路、水体屏障

建筑选择、组团、移位与变形共用同一套街坊和路水约束。每个设计房院记录所属街坊、相邻街路、水道或岸侧、入口接点；设计足迹及檐口外包络均参加占用检查。

最近空格搜索只能在原对象允许的同侧连通区域内进行。找到直线距离更近的另一岸或另一街坊，不构成可用位置。窄水道转换为带状表达后仍是屏障；道路加宽后同步回退房院边界；桥头保留上下游水面与道路衔接。跨水桥本身作为特定类型对象处理。

## 4. 减少房屋数量，留下完整房与院落结构

每座入选民房采用与参考作品相称的完整体素资产：台基/地基过渡、墙体和山墙、门窗开口、门框窗框、檐下、分层屋顶、屋脊、必要院墙与入口。近看和绕看时，正面、侧面、背面与上方均有完整形体。完整资产的具体构件基线与技术组织见同目录《重规划_体素架构建议》。

普通入选屋舍与重点古建共用完整性要求，地方类型和识别特征各自设计。普通民房允许复用构件和类型模板；宽度、开间、层数、门窗节奏与院落组合应通过离散参数变化，避免任意拉伸。候选构件单位沿用参考作品的 0.2 设计米，先在样件试制中校准。

组团设计按以下顺序进行：

1. 识别来源聚落的临街/临水边缘、街坊边界、主要方向和疏密梯度。
2. 选择能表达这些关系的完整房院。连片街面、山坡散居、临水后院和现代镇区分别采用合适类型。
3. 把院落视为“房屋＋院墙＋留空＋入口路径”的组合；把连续街巷视为两侧建筑和中间负空间的共同结果。
4. 减少内部重复房屋和开间，保留必要的前后进、主次屋顶与院落节奏。古建整体依据已知布局设计，缺失部分单列推定。
5. 检查整组从街口、院内、湖岸和俯视的读法，再决定删选数量与设计区域大小。

远景可以合并提交、剔除不可见面、使用保持轮廓和院落开口的几何LOD；每个入选对象始终有可恢复的完整近景资产。总图里看不见窗格是投影结果；拉近后只能看见墙盒加简顶则是资产缺失。普通房屋同样允许靠近检查。

## 5. 十几公里范围与参考密度的解决路线

| 路线 | 能解决什么 | 代价和适用条件 |
| --- | --- | --- |
| 全域按源比例连续表达 | 地理距离关系最容易解释；相机可跨区域连续移动 | 全景中房屋投影很小。需要片区视角和分块加载，不能要求全域同屏时每栋近景细节可见 |
| 全域总图＋同一设计世界的连续片区 | 有全域认识，也能在重点片区进入完整房院；共享身份与空间组织 | 需要综合设计与约束审查。非均匀压缩改变局部距离，须记录人工设计性质 |
| 全域总图＋独立片区场景 | 各片区容易维持适合近看的尺度；试制与装载相对独立 | 场景切换承担尺度变化；片区间步行距离与完整连续性无法由独立场景证明 |

**推荐第二条。** 先建立陆巷连续样区，确定完整房院、街巷和岸水关系所需的设计空间，再向相邻坡地、湖岸与连接走廊延展。全域总图是该设计世界的远景视角，片区视角沿同一套 C 坐标进入；切换相机与LOD时，同一对象保持身份、锚点和拓扑关系。

空间压缩属于人为内容设计，会改变真实距离、面积和部分局部角度，换取完整对象、清晰通路和可读密度。优先保留山湖轮廓、相对方位、层级、沿线次序与连接关系。设计图上的长度不能直接解释为现实步行距离或测绘比例；地理核查始终回到 G 坐标，并在并列图中展示主要变形。

全域总图可加强主山脊、岸线和聚落纹理的整体识别，但不要求十几公里全域和门窗构件在同一屏幕同时可辨。艺术密度由选中房院、道路留空、林冠块面与水面留白共同建立。镇区可以密集，古村可以紧凑，山坡茶果林仍需有疏散和停顿；不能把参考作品的城池密度均匀覆盖东山。

独立片区场景适合作为构件试验台、证据不足古建的形制研究展台，或尚未纳入连续世界的后续章节。确需采用独立场景时，用明确的导航切换说明场景身份，保留源位置索引；它不能被表述为已完成全域连续地理。

## 6. 三个具体转换例子

以下说明操作逻辑，涉及的删选数量、距离与压缩率均待样区测试决定。

| 来源情况 | 综合设计操作 | 保留与检查 |
| --- | --- | --- |
| 某条街两侧有大量同质重复住宅，街后有院落和一条水道 | 选择少量完整沿街房与院落组合，减少重复段；缩短这段街路，把街后水道、院门和连接巷同步映射到设计位置 | 街路仍连续，房屋街侧与水侧不颠倒，入口可达；院内仍是可见空隙，不用一条巨型屋顶填满 |
| 片区核心与湖岸之间有较长的同质过渡空间 | 压缩该过渡区，为核心与水陆接口保留足够的完整表达空间；岸线与进村道路使用共同控制对象 | 从湖岸到村内的先后层次与路径关系成立，码头仍接陆地，港道仍通湖；压缩量标为设计选择 |
| 三山岛与东山主体需要同图可见，远景中间水域较空 | 总图机位共同框入岛与半岛；若设计层缩短岛陆间隔，联动审核岸线方位、相对位置和水面留白 | 岛保持独立陆地，水域间隔清楚；不把三山岛移到另一岸、不与半岛焊接。源距离与设计距离分别保留 |

每个例子的建筑身体继续使用完整构件尺度。空间压缩削减的是重复内容和连接距离，具体的加宽、放大、移位与高度强化另列参数。

## 7. 陆巷样区的边界与证据分阶段

### 已有可靠起点

陆巷村 OSM 点 `node/5939534286` 为 WGS84 `[120.3564852, 31.0762724]`，可作为查找聚落和组织样区的来源锚点。该点不等于古村边界，也不能单独定位紫石街、惠和堂或寒山港。现有 OSM 道路、水体和 Overture 房屋足迹可支持周边地理骨架与普通房群的选取；类型化房屋的形制依据与足迹来源分别记录。

现有地方图文提供陆巷街巷、港道、湖岸及惠和堂等对象的身份和形制线索。惠和堂参考平面缺少已核实比例尺与地理配准；若干重点古建、紫石街和寒山港尚无可确认的现有几何匹配。附近任意水道不能直接命名为寒山港，任意大院也不能直接命名为惠和堂。

### 分阶段推进

| 阶段 | 可做内容 | 进入下一阶段的门槛 |
| --- | --- | --- |
| L0：资产与尺度试验 | 在独立试验台制作完整普通民居、沿街房、院墙和树木；惠和堂可做带来源的形制研究样件 | 在固定机位下，完整性、方阶构件、比例与房树关系通过；古建研究样件保持“未落位”身份 |
| L1：陆巷已知骨架样区 | 以可靠村点和现有路水/足迹选取一个相连片区，制作完整类型化民房、院落、岸坡与通路 | 来源对应、街坊同侧、岸水接合与可进入观看通过；范围按实际相连要素确定，不先划固定正方形 |
| L2：地方节点落位 | 核实古街、寒山港水口与关键古建的大致占地、朝向、相邻关系；再把已研究形制附着到可定位对象 | 至少有能校核的可靠位置/平面对应和关系证据。仅有文字身份或一张无定位照片时，继续保留待核项 |
| L3：连续片区扩展 | 把核心、港岸、坡地和相邻聚落设计为连续体验，接入全域总图 | 跨片区的控制点、网络、变形过渡与LOD稳定通过，重点节点资料状态清楚 |

L1 可以验证完整体素与制图综合方法。陆巷“古街—特色宅院—寒山港—太湖”地方关系的专项验收在 L2 完成资料对应后开展。某处缺少定位证据时，保留其未落位条目，不往地图上补一个看似精确的坐标。

## 8. 固定观看条件后再定密度

先建立可复现的验收机位，再进行删选与压缩。建议首轮主画布为 1440 × 1000 px、DPR=1、垂直 FOV=45°；这是一组待样区确认的测试条件。侧栏关闭或固定占用范围，记录有效三维画布尺寸。冻结相机位置、目标点、昼间光照、雾、曝光和阴影设置，先看正常光照下的几何与关系，再看气氛。

记录三类固定视角：

- **完整资产转台与接近路径：**对象在画面中占固定大小，检查正、背、侧、俯视与门前视角；起始可让主体占画面高度约四分之一至三分之一，再与参考同等屏幕占比比较。
- **片区斜俯视与沿街路径：**屋舍、巷道、院落开口与水口可辨，能比较疏密和通路；重要构件的像素门槛由通过的样件冻结。
- **全域总图：**固定半岛与三山岛联合构图，检查主次、山湖和聚落分布；全域镜头不代替单体与片区验收。

透视下可以用 `px ≈ Hpx × size / [2 × depth × tan(FOVv/2)]` 估算投影量级，再以实际渲染测量复核。FOV、视距、画布高度和有效UI区域必须一起记录。不能更换更有利的相机或通过浓雾隐藏问题后声称密度与细节达标。

## 9. 验收指标：设计密度与硬关系并行

### 9.1 需要全部满足的关系项

| 检查项 | 验收方式 |
| --- | --- |
| 水陆与山村关系 | 对照源坐标和设计坐标各一张关系图；半岛、三山岛保持分离，主要水口通湖，山脊—坡脚—聚落—岸线层次成立 |

| 街坊与水岸屏障 | 所有入选房院审查同侧归属、设计占用包络和入口接点；跨街、跨水误归属与未经说明的碰撞为零 |

### 9.2 在设计坐标中判断疏密

建筑覆盖率采用 `R_design = 完整房屋设计足迹并集面积 / 设计街坊可布置面积`，并统一是否计入院墙、檐口与门廊。街坊可布置面积按同一口径扣除必保道路、水体和明确保留的空地。以已通过的样区确定各类型的目标区间，古村核心、现代镇区与山坡散居分别设定。

同时记录临街连续程度、沿水边界节奏、院落开口与巷道的屏幕宽度、屋顶大小分布、建筑/林冠的视觉层级，以及密集核心到外围的梯度。面积指标不能单独证明空间肌理成立。

源建筑覆盖量用于理解原聚落的类型和梯度，来源计数用于追踪选择。设计坐标改变后，不能直接用源面积当设计覆盖率分母。上一版约 30% 的矩形占地量可诊断旧符号过稀；新方案的通过线由设计坐标、完整房院和固定镜头共同建立，不要求回到源面积的 100%，也不沿用 30% 作为目标。

### 9.3 对照和稳定性

参考对照统一对象屏幕占比和观看条件，比较体素构件、屋顶层次、灰瓦白墙、负空间、林木组织和雾层。地方辨识同时对照东山资料，保留本地山湖、古村和茶果林的关系。

同一场景从总图进入片区、从街口进入院落，再返回总图时，对象身份、锚点、路水关系与设计密度保持稳定。性能调整针对装载、几何提交、阴影与后处理，场景内容的取舍由离线设计版本确定。

## 10. 规划落地时的提交顺序

1. **关系与证据稿：**源范围、已定位对象、待定位对象、必保关系图和初步样区边界。
2. **完整资产与屏幕尺度稿：**普通房、沿街房、院落和树木的完整样件；固定FOV/画布/机位的参考对照，冻结通过的构件尺度。
3. **样区内容设计稿：**选入/删去清单，完整房院组合、街水保护走廊、设计密度与必要夸张；提供 G 与 C 的并列图。
4. **约束压缩稿：**压缩区、稳定核心、过渡区及映射参数；列出距离、占地和山势表达的主要变化与保留关系。
5. **连续样区验收稿：**固定全景、片区和接近路径；检查表、设计密度与人工审查结果。样区通过后再扩展。
6. **全域扩展稿：**形成相连的片区与通路，保留清楚的半岛/岛屿/背景陆地层级；每次扩展继续沿用已通过的单体精度标准。

设计台账建议至少包含：`designId`、`sourceIds`、`sourceGeometry`、`designGeometry`、`assetKey`、`evidenceLevel`、`operation`、`parentBlock`、`barrierSide`、`entryLink`、`deformationRegion`、`heightPolicy` 和 `reviewStatus`。类型化、概括、夸张、移位和未落位是可查询的状态，不能被覆盖成真实地理测量值。

本方案以已核验的源数据、原作学习档案、现有制图综合规范及回滚自查为依据。本轮产物为规划文件；下一步实施从完整资产试验和陆巷关系稿开始。
