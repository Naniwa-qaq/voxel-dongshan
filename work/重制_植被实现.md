# 重制版植被资产实现

日期：2026-10-20。代码：`东山镇_重制版/js/vegetation.js`。

本轮直接实现完整近景资产。植物形体采用江南场景可用的概括类型，未据此推定东山逐株位置、树种或现实尺寸。

## 接口与输出

```js
const information = DSVegetation.build(builder, {
  type: 'broadleaf', // broadleaf | willow | orchard | bamboo | pine
  seed: 31415,
  scale: 1
});
```

`builder.box(x,y,z,w,h,d,hexColor)` 接收中心位置、尺寸和数字 `0xRRGGBB` 颜色。树根位于局部坐标 `(0,0,0)`，Y 轴向上。模块无 THREE 或其他依赖。外部负责实例位置、地形接地与光照。

返回实际 `height`、`radius`、`bounds`、`boxes`、`woodBoxes`、`leafBoxes`、`type`、`seed`、`scale`、`grid`，可用于避让屋檐和控制相机。`radius` 是 X/Z 两方向轴向半径的最大值，属于保守轴向包络；斜向的圆形碰撞检测应读取完整 `bounds` 后另算。

所有最终盒面按 **0.2 米**取整；`scale` 改变植株总体尺寸后重新对齐盒面，最小尺寸仍为 0.2 米。传入值限制在 0.5–1.6，常规场景推荐采用下表的窄范围，避免一街树木尺度混乱。

## 五种形体

| 类型 | 形体构造 | 推荐 scale | seed=31415、scale=1 实际包围尺寸与成本 |
|---|---|---|---|
| broadleaf | 根颈、延续到冠内的渐细主干、7 组低肩主枝、6 组错开中层枝、4 个不同顶高，合计 37 组偏心叶簇；冠体从约 4.3 米延伸到 9.4 米 | 0.85–1.1 | 高 9.4 米，最大轴向冠幅约 8.8 米；880 盒（287 干枝、593 叶） |
| willow | 渐细主干、9 个细拱形分枝、立体顶部和肩部叶簇、每枝 6 组长短不同的细阶梯下垂叶带 | 0.9–1.05 | 高 9.0 米，最大轴向冠幅约 9.6 米；1353 盒（315 干枝、1038 叶） |
| orchard | 低处分叉、7 组向外展开主枝、二级枝与相接的小冠；不预设枇杷/杨梅树种 | 0.85–1.05 | 高 5.8 米，最大轴向冠幅约 6.0 米；373 盒（132 干枝、241 叶） |
| bamboo | 7 根高度不同的节秆、错开节点、侧枝和成扇扁叶簇；秆间与叶扇间透空 | 0.85–1.05 | 高 8.0 米，最大轴向宽约 4.4 米；602 盒（266 秆枝、336 叶） |
| pine | 连续弯折主干、4 层不规则横展分枝，每枝两组分离但相承的扁冠 | 0.9–1.1 | 高 9.2 米，最大轴向冠幅约 8.4 米；672 盒（211 干枝、461 叶） |

果树主动采用较低树高，不将所有类型统一放大为 8–12 米乔木。竹丛作为单个完整资产，不能把其 `radius` 误当成一根竹的占地。

## 构造及色彩

干枝采用短盒搭接的数字阶梯。每个短盒覆盖所属线段的一段及宽度，因此转弯处具有真实交接体积。没有斜圆柱、斜棱柱、球冠、锥体或透明叶片。

一组叶簇由相接的中心扁体、偏移顶部、5–6 个侧小冠和边缘细块组成。细块用于冠缘，内部仍有成组的叶量。阔叶树的低层叶群包住肩部，独立的中层枝与不齐平的顶部形成完整三维冠体，避免裸枝汇成杯形后托着一层扁平叶伞。不同枝扇的方位与高度错开，保留枝干可读的局部冠隙。

柳的下垂叶带以 0.2 米为主体宽度、长度约 3.35–4.95 米，逐格偏移并保持相接，分散成每主枝六组而非粗大触手。上部肩冠与顶部叶簇也有竖向体积。竹的叶扇由逐渐缩短的交错扁条组成。

| 用途 | 色板（从冠内至明部） |
|---|---|
| 阔叶 | `#526b3c #607b43 #6c884c #7a9656 #8ba465` |
| 柳 | `#667b40 #758b49 #829953 #92a762 #a0b271` |
| 果树 | `#48643c #557346 #62814b #738e53 #829b62` |
| 竹叶 | `#5f783e #6b8747 #7a9652 #8ba55e #9bb46e` |
| 松 | `#3e5940 #4a6849 #587650 #66865a #78966a` |
| 一般干枝 | `#64513e #746049 #827052 #918064` |

颜色按叶簇的层级和分枝角色选用。光照应承担面向区分，不能在构建器内再次把颜色统一乘暗，否则会重现失败原型中的暗绿碎点。推荐白昼、低雾先核树形，再加入晨暮环境。

## 已完成的验证

1. Node `--check` 语法检查通过。
2. 五类型 seed=31415、scale=1 的全部顶点面位置均对齐 0.2 米，尺寸和坐标均有效，最小盒边不小于 0.2 米。
3. 五类型 × 五 seed（1、5、42、371、31415）× 五 scale（0.5、0.75、1、1.25、1.6）共 **125 个资产**，逐盒 AABB 邻接遍历均能从根部到达全体盒子，没有孤立枝段或悬空叶簇。该项验证实际几何连接，不将视觉重叠当作连接。
4. 第二轮修改后重新检查上述 125 组组合，全部仍连通。盒数范围：阔叶 863–888；柳 1337–1371；果树 367–375；竹 602–608；松 669–679。没有按全冠细胞填充而产生数十万独立盒。

## 场景截图驱动的第二轮修正

已实际检查 `东山镇_重制版/qa/tree.png` 和 `waterfront.png` 的初次渲染。第一轮虽然网格和连接验证通过，但画面中阔叶的主枝粗且集中，形成深色杯形和过扁的冠层；柳叶条显得粗短、主干上部显得柱心过重。该画面没有被当作美术通过。

本轮针对形体修改，未靠整体压暗色板掩盖问题：将分枝阶梯长度从 0.42 米缩至 0.3 米；阔叶主枝细至 0.2 米、叶簇由 21 组增至 37 组并分成低肩、中层和不齐顶部；柳主干缩至 0.5 米渐细、主枝缩至 0.2 米，增加冠宽和冠高，改用六组细长叶带。最终轮廓需由更新后的场景截图再次核查。

连接和网格验证不代替画面验收。集成后仍需白昼下的正侧轮廓、冠下仰视、屋树组合三类机位，核查枝干可见、至少两个冠隙可读、树与檐口和通路不穿插。单株资产不会自动决定散布位置。
